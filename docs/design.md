# 設計書（STEP 1〜5 承認済み事項）

個人用 TOEIC 英単語学習Webアプリの設計をまとめる。ここに書かれた内容はユーザーの承認済み事項。
変更する場合は、ユーザーの承認を得てからこの文書を更新する。

最終更新: 2026-11-18

---

## 1. 目的と前提

- TOEIC 800点を目標とした英単語学習。開始レベルの想定は CEFR A2（設定で変更可能）。
- 単語学習に限定する。Listening・Reading 対策は外部教材と併用する。
- **個人利用のみ。配布しない。** 利用者は本人の Google アカウントだけに制限する。
- 最優先の非機能要件は **学習履歴を失わないこと**。

## 2. 固定要件（ユーザー設定で変更しない）

- 出題形式: 4択（英→日、日→英、英文穴埋め）
- 開発担当: Claude Code
- アプリ形態: Webアプリ（PWA）
- 対応端末: Windows PC、スマートフォン（レスポンシブ対応必須）

## 3. 承認済みの決定事項

| U2 | データの作成 | 意味・例文・選択肢は開発時に Claude Code が下書き → 自動検証 → ユーザーのレビュー → 承認済みのみ出題。実行時の AI 生成はしない |

## 4. システム構成

```
[ブラウザ / PWA]  React + TypeScript + Vite
  ├─ UI層        画面・部品
  ├─ アプリ層    日次セッション管理、出題配分、採点
  ├─ ドメイン層  純粋関数（FSRS の適用、定着判定、配分、集計、学習日の計算）
  ├─ データ層    Dexie（学習データの正本 + 単語・問題データのキャッシュ）
  └─ 同期層      送信待ちキュー → Firestore / Firestore → 差分の取り込み
[Firebase]  Authentication / Cloud Firestore / Hosting（Spark プラン）
```

フォルダ構成:

```
src/domain/    純粋関数（単体テストの中心）
src/content/   単語・問題データの型と読み込み
src/data/      Dexie のスキーマと読み書き
src/sync/      送信待ちキュー、送信、差分の取り込み
src/features/  home / daily / weekly / wordbook / history / settings / migration
src/ui/        共通部品
content/       単語・問題データ（JSON、バージョン付き）
tools/content/ 品質検証（V01〜V13）
```

## 5. データ設計

### 5-1. 単語・問題データ

型は `src/content/types.ts` を正とする。

- 単語ID は綴りから作らず、一度使った ID は再利用しない。廃止は `status: "deprecated"`。
- 公開済みの問題は書き換えない。修正は `version` を上げた新しい版を追加し、旧版も残す。
- 本番に含めるのは `review.status = "approved"` の問題だけ。

### 5-2. 自動品質検証（`npm run validate:content`）

| ID | 内容 | 不合格時 |
|---|---|---|
| V01 | 形式・必須項目 | エラー |
| V02 | ID の重複・参照先の存在 | エラー |
| V03 | 選択肢がちょうど4件、正解番号 0〜3、正解が対象語を指す | エラー |
| V04 | 正規化後の選択肢の重複 | エラー |
| V05 | 正解の漏れ（問題文に正解・活用形が含まれない） | エラー |
| V06 | 誤答が正解の別訳・類義語・活用形でない | エラー |
| V07 | 誤答の品詞が正解とそろう（穴埋めは品詞の違いを問う出題があるため警告） | エラー / 警告 |
| V08 | 穴埋め: 空欄1か所、6〜25語、末尾の句読点、余分な空白なし | エラー |
| V09 | 本番データは承認済みのみ | エラー |
| V10 | 公開済みの問題の内容が変わっていない（`content/manifest.lock.json` と比較） | エラー |
| V11 | 公開済みの単語ID が消えていない | エラー |
| V12 | 有効な単語に3形式の承認済み問題がそろう | 警告 |
| V13 | 例文の重複 | 警告 |

人によるレビュー: 正解が1つに決まるか、英文が自然か、誤答の紛らわしさが適切か、解説が正確か、既存教材の文章を流用していないか。

### 5-2-1. 難易度帯の決め方

| 出典 | 順位 | 難易度帯 |
|---|---|---|
| NGSL 1.2（SFI順位） | 1〜500 / 501〜1000 / 1001〜1800 / 1801〜 | 1 / 2 / 3 / 4 |
| TSL 1.2のみ（TSL順位） | 1〜200 / 201〜700 / 701〜 | 3 / 4 / 5 |

TSL の語は一般的な頻度では NGSL の範囲外のため、帯3以上とする。

### 5-2-2. データ作成とレビューの流れ

1. 下書き: `tools/content/drafts/<名前>.ts`（Claude Code が作成）
2. 書き出し: `npm run content:build-draft -- <名前>` → `content/words`、`content/questions`、`content/review/<名前>.csv`
   - 解説は、穴埋めの理由説明（下書き）に、訳と誤答の意味をデータから自動で付け足して作る
   - 出力先が既にある場合は停止する（レビュー済みの内容を上書きしないため）
3. レビュー: CSV を Excel / Google スプレッドシートで開き、「状態」に 承認 / 要修正 / 未確認、「修正内容・メモ」に指摘を入力
4. 取り込み: `npm run content:import-review -- <名前> <CSV>` → 品質検証に合格した場合だけ保存
5. 要修正の問題は Claude Code が直して再提出する

### 5-3. 学習データ（Dexie）

```ts
db.version(1).stores({
  events:          'eventId, [wordId+answeredAt], studyDate, [mode+studyDate], sessionId', // 正本・追記のみ
  drafts:          '[sessionId+position]',
  sessions:        'sessionId, [mode+studyDate], status',
  wordbook:        'wordKey, updatedAt',
  customWords:     'customWordId, headwordNorm',
  settings:        'id',
  settingsHistory: 'changeId, changedAt',
  legacy:          'legacyId',
  cardStates:      'wordId, dueDate',            // 導出データ
  mastery:         'wordId, status, checkDueDate', // 導出データ
  contentWords:    'wordId, band',
  contentQuestions:'[questionId+version], wordId, type',
  outbox:          'outboxId, nextRetryAt',
  meta:            'key',
})
```

- **AnswerEvent**: eventId（UUIDv7）、schemaVersion、deviceId、sessionId、mode（daily / weekly / practice）、出題理由、questionId、questionVersion、wordId、senseId、type、選択肢の並び、選んだ番号（時間切れは null）、正誤、変更回数、回答時間、表示時刻、回答時刻、時差、studyDate、切り替え時刻、appVersion、dataVersion。変更・削除しない。
- 「FSRS・定着判定に反映するか」は保存せず、毎回導き出す（同じ単語・同じ学習日の daily 回答のうち最も早いもの。同時刻は eventId で判定）。
- 単語帳の誤答回数・最終学習日・復習予定日・定着状態は保存せず、回答イベントと導出データから計算する。
- 単語帳の登録理由は端末間で足し合わせる（理由 ID で重複除去、自動登録は `auto:{eventId}`）。削除フラグとメモは最終更新を優先。

### 5-4. Firestore

`users/{uid}/events/{eventId}`、`wordbook/{wordKey}`、`customWords/{id}`、`settings/current`、`settingsHistory/{changeId}`、`legacy/{legacyId}`、`snapshots/{yyyymm}`、`content/current`、`content/{版}/chunks/{n}`。

- すべて本人の uid のみ読み書き可能。回答イベントは作成のみ許可（更新・削除は禁止）。
- 送信: 回答の確定・単語帳の変更 → 送信待ちキュー → 起動時・オンライン復帰時・画面復帰時・5分ごと。失敗時は間隔を倍々に延ばす（上限1時間）。
- 受信: serverAt が前回位置 − 5分より新しいものを取得し、eventId で重複除去 → 影響した単語だけ再計算。
- バックアップ: 全データの JSON 書き出し（スキーマ版・SHA-256 チェックサム付き）。読み込みは eventId で統合し、既存データを消さない。

## 6. 復習アルゴリズム

### 6-1. FSRS

- 正解 = Good、誤答 = Again。回答時間は記録のみで評価に使わない。
- 1単語につきカード1枚。その日最初の daily 回答だけを反映する。
- 期限: カードの dueAt を学習日に変換し、今日以前なら期限が来たとする。
- 設定変更時は回答イベントから全再計算する（イベント自体は変更しない）。

### 6-2. 定着判定（初期値: 連続正解 R=2、別日必須、確認まで K=7日）

| 現在の状態 | 正解 | 誤答 |
|---|---|---|
| 未学習・学習中（連続 k） | k+1。R に達したら確認待ち（確認日 = 学習日 + K） | 学習中（k=0） |
| 確認待ち・確認日より前 | 変化なし | 学習中（k=0） |
| 確認待ち・確認日以降 | 定着 | 学習中（k=0） |
| 定着 | 変化なし | 学習中（k=0）、「過去に定着」を記録 |

週次テスト・練習問題・移行データは影響しない。条件変更時はルールの版を上げて再計算し、旧ルールの結果も残す。

### 6-3. 出題候補と二重出題の防止

- 確認候補（確認日 ≤ 今日）と復習候補（FSRS の期限 ≤ 今日）を単語 ID でまとめ、1単語1日1問。1回の回答を両方に反映する。
- 優先順位: 確認候補（確認日が古い順）→ 復習候補（想起確率が低い順 → 期限超過日数 → 単語ID）。

### 6-4. 新出と復習の配分

```
fAcc  = acc7 < 0.75 ? 0.5 : acc7 < 0.85 ? 0.8 : acc7 ≥ 0.92 ? 1.2 : 1.0   （復習回答20件未満なら1.0）
fBack = B > 1.5N ? 0 : B > N ? 0.5 : 1.0      （復習の優先度 低/標準/高 で 2.0N / 1.5N / 1.0N）
fLoad = load7/7 > 0.8N ? 0.7 : 1.0
fTime = sessT > 1.2 × Tmax ? 0.8 : 1.0
floor = newMax == 0 ? 0 : gap ≥ 3 ? max(newMin, 3) : newMin
newTarget = clamp(round(newBase × fAcc × fBack × fLoad × fTime), floor, newMax)
reviewSlots = min(B, N − newTarget)
newSlots = reviewSlots < N − newTarget ? min(newMax, N − reviewSlots, 出題可能な新出) : min(newTarget, 出題可能な新出)
```

- 不足時は理由を表示し、FSRS の予定は早めない。「練習問題で補充」は mode = practice（反映しない）。
- 積み残しは翌日に持ち越し、件数を表示する。
- 乱数はセッション ID を種にして再現可能にする。

### 6-5. 問題形式

- 初出は英→日。復習は設定の割合で重み付けし、前回と同じ形式・14日以内の同じ問題を避ける。
- 確認問題は最後に正解した形式とは別の形式。

### 6-6. 週次総復習

- 対象は日次学習で1回以上答えた単語。想起確率が低い単語・最近誤答した単語を重く抽選。
- 対象不足時はその件数で実施するか選べる。10問未満は実施不可（理由を表示）。
- 開始時に終了時刻を保存。時間切れの未回答は selected = null で記録し、正答率とは別に表示。

## 8. UI

- スマートフォン: 下部タブ（ホーム／学習／単語帳／履歴／設定）。PC（1024px以上）: 左固定メニュー、本文最大幅 880px。
- 回答: タップで選択 → 「次へ」。採点前は「前へ」で変更可。PC は 1〜4 キーで選択、← → で移動、Enter で採点。
- 正誤は「○ 正解」「× 不正解」の記号と文字、左の線、背景色で示す（色だけに頼らない）。
- 週次テストは残り時間を常時表示し、残り5分で通知。
- 新しい版の通知は学習中に出さず、ホームに戻ったときに表示する。
